---
name: spec-driven-feature
---
Use for feature/delivery work.

1. Read explicit requirements and repository contracts before editing.
2. For ambiguous behavior, resolve from supplied docs/tests/code first; ask only for a genuinely blocking product decision.
3. Convert the requested scope into a short internal checklist of observable acceptance criteria.
4. Implement the smallest coherent change that satisfies that checklist.
5. Add or update regression coverage for changed behavior when a test suite exists.
6. Do not report completion until verification maps back to the acceptance criteria.
